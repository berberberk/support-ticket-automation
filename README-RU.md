## Что решаем?

Онлайн-сервис получает около 200 тысяч обращений в сутки через чат, почту, веб-форму и мобильное приложение. Типовые обращения нужно быстро направлять в нужную очередь и готовить для них черновик ответа, но инциденты с безопасностью аккаунта, спорными платежами, кодами подтверждения или недостаточными основаниями нельзя обрабатывать автоматически. Решение должно сокращать время первого ответа, не раскрывать персональные данные и сохранять след каждого автоматического решения.

## Что делает система?

Система нормализует обращение, создаёт `request_id`, скрывает электронную почту и телефон, проверяет запрещённые для автоматизации категории и определяет тему с маршрутом. Безопасное обращение с достаточным основанием из базы знаний получает черновик; рискованное, неоднозначное или не подтверждённое источником обращение передаётся оператору без автоматического ответа. Все решения записываются в журнал аудита без исходного текста тикета.

## Что реализовано, а что спроектировано?

**В PoC реализованы:** локальный конвейер с правилами риска и классификацией по ключевым словам, лексический поиск по небольшой базе знаний, детерминированный черновик, журнал в JSONL, FastAPI-интерфейс, проверки обычного, рискованного и отказного сценариев. По умолчанию PoC полностью работает локально и не требует сети, ключа или внешнего сервиса.

Дополнительно реализованы, но выключены по умолчанию, адаптеры Qdrant/FastEmbed и OpenRouter. Qdrant проверен в памяти с подставными векторами; реальный FastEmbed и реальный запрос в OpenRouter во время экзамена не запускались. Внешний генератор получает только обезличенный текст и одну статью из утверждённой базы знаний; при его ошибке тикет передаётся оператору.

**В целевой архитектуре спроектированы:** независимый быстрый контур, надёжная очередь и фоновые исполнители для медленной обработки, постоянные хранилища тикетов и аудита, производственное обслуживание моделей, отдельная служба работы с персональными данными, интерфейс оператора и полный контур обучения моделей. FastAPI в PoC синхронно вызывает локальный конвейер и не имитирует очередь или фоновых исполнителей.

## Запуск

Для полного PoC нужен `uv`. Проект совместим с Python 3.11+, основной сценарий проверен на Python 3.12. `uv sync` сам создаёт локальное окружение `.venv`, поэтому вручную вызывать `python -m venv` не требуется. Версии зависимостей зафиксированы в `pyproject.toml` и `uv.lock`.

Если `uv` ещё не установлен:

```bash
# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# либо на macOS через Homebrew
brew install uv
```

При необходимости Python 3.12 можно установить через `uv`:

```bash
uv python install 3.12
```

После этого выполните:

```bash
uv sync
uv run python demo.py
uv run python evaluate.py
uv run python -m unittest discover -s tests -v
```

HTTP-интерфейс:

```bash
uv run uvicorn app:app --host 127.0.0.1 --port 8000
curl http://127.0.0.1:8000/health
```

Обычное обращение возвращает `draft_ready` и найденную статью:

```bash
curl -X POST http://127.0.0.1:8000/tickets \
  -H 'Content-Type: application/json' \
  -d '{"request_id":"api-demo-1","channel":"web","text":"Не могу войти в аккаунт, как восстановить пароль?"}'
```

Рискованное обращение возвращает `needs_review`, маршрут `human_operator` и `draft: null`:

```bash
curl -X POST http://127.0.0.1:8000/tickets \
  -H 'Content-Type: application/json' \
  -d '{"request_id":"api-risk-1","channel":"web","text":"Мой аккаунт взломали, был несанкционированный вход."}'
```

Для необязательных адаптеров скопируйте шаблон локальной конфигурации:

```bash
cp .env.example .env
```

После этого измените нужные значения в `.env`. Сам `.env` добавлен в `.gitignore` и не должен попадать в репозиторий.

```bash
# семантический поиск
RETRIEVAL_BACKEND=qdrant

# внешний генератор
GENERATOR_BACKEND=openrouter
OPENROUTER_API_KEY=...
```

Без ключа OpenRouter и без настройки Qdrant фабрика сохраняет локальные детерминированные компоненты. Для демонстрации выбранных адаптеров используйте `uv run python demo_rag.py`.

## Бизнес-ценность

Около 40% потока, то есть примерно 80 тысяч обращений в сутки, относятся к типовым и повторяющимся. Основная бизнес-гипотеза — сократить ручное время на этой части потока относительно текущих ≈8 минут и 150 ₽ на обращение: маршрутизация уменьшает объём первичной сортировки, а черновик по утверждённой базе знаний сокращает время подготовки ответа. На пилоте эффект нужно измерять в сэкономленном времени операторов и времени до первого полезного ответа, сохраняя SLA 15 минут, CSAT не хуже базовых 4,2/5, долю повторных обращений около 9% и ограничения безопасности. LLM имеет смысл использовать только в категориях, где он даёт измеримый выигрыш относительно более дешёвого варианта «поиск по базе знаний + шаблон».

## Ограничения

- Риск, тема и уверенность в PoC определяются детерминированными правилами и не являются производственными моделями.
- Поиск по умолчанию лексический и использует четыре локальные статьи; оценка качества синтетическая и малая.
- Проверка обоснованности детерминированного черновика строковая; семантическая оценка внешней LLM требует отдельного набора и ручной проверки.
- В PoC нет очереди, повторных попыток, постоянного хранилища статусов и интерфейса оператора; это части целевой архитектуры.
- Числа `LOCAL_DECISION_BOUNDARY=0.60` и `MIN_RETRIEVAL_SCORE=0.20` нужны только для демонстрационных примеров, а не выбраны по калибровке.
