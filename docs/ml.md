# Выбор методов и оценка качества

Система использует методы по возрастанию стоимости: правила безопасности, лёгкая классификация, поиск по базе знаний и только затем LLM. Это оставляет быстрый контур коротким и объяснимым, а свободную генерацию применяет лишь после нахождения основания для ответа.

| Компонент | PoC | Целевой подход и источник |
|---|---|---|
| Риск | Правила по маркерам опасных случаев | Правила, согласованные с поддержкой и безопасностью; при достаточной разметке — внутренний классификатор риска |
| Тема и маршрут | Ключевые слова и демонстрационная оценка уверенности | TF-IDF с логистической регрессией или линейной SVM, обученной на исторических обращениях |
| Поиск | Лексическое пересечение слов по локальной базе знаний | Гибридный поиск по утверждённой базе знаний и обезличенным решённым обращениям; при необходимости — открытая многоязычная модель векторов |
| Черновик | Детерминированный шаблон | Внешняя LLM через OpenRouter только для асинхронного черновика по найденному основанию |

## Правила безопасности

**Задача.** Запретить автоматическую обработку опасных категорий, скрыть обрабатываемые персональные данные и задать очевидные маршруты эскалации.

**Базовый и кандидатный подход.** Базовый вариант — явные правила по категории, признакам и наличию PII; именно он реализован в PoC. В целевой системе правила остаются обязательным верхним слоем и дополняются согласованным перечнем разрешённых и запрещённых действий.

**Данные и разметка.** Нужны версионируемые правила, исторические обращения и итоговые решения операторов. Разметка рискованных случаев должна проверяться специалистами поддержки и безопасности.

**Метрики.** Важнее всего полнота обнаружения опасных категорий и доля их пропусков. Дополнительно контролируются точность, доля эскалаций и время работы правил.

**Сбой и неопределённость.** Конфликт правил, неизвестная категория, неполный вход или невозможность безопасно минимизировать данные ведут к оператору. Генератор не может отменить решение правил.

## Классификация темы и маршрута

**Задача.** Быстро определить тему обращения и очередь обработки. Отдельный классификатор риска имеет смысл только при достаточной исторической разметке и всегда работает после жёстких правил.

**Базовый и кандидатный подход.** Базовый вариант — наиболее частый маршрут по теме. Первый реалистичный кандидат — TF-IDF с логистической регрессией или линейной SVM для ограниченного числа тем. Такой классификатор дешёв, объясним по признакам и не требует внешнего API, поэтому подходит для быстрого контура.

**Данные и разметка.** Используются нормализованные исторические обращения, их окончательная тема, очередь и решение оператора по риску. Повторные обращения одного инцидента нельзя разносить между обучающей и проверочной выборками.

**Метрики.** Для темы и маршрута: macro-F1, полнота по каждому классу, матрица ошибок и задержка. Для риска: полнота опасных классов, доля пропусков и доля обращений, направленных оператору; общая точность недостаточна.

**Сбой и неопределённость.** Незнакомая тема, конфликт признаков, высокий риск или недостаточная уверенность ведут к оператору. Демонстрационная граница PoC не является производственным порогом.

## Поиск по базе знаний

**Задача.** Найти статью базы знаний или обезличенное историческое обращение с подтверждённым решением до подготовки черновика.

**Базовый и кандидатный подход.** Базовый вариант — BM25 либо TF-IDF по небольшой локальной коллекции; в PoC реализован ещё более простой лексический поиск. Необязательный `QdrantRetriever` использует Qdrant в памяти и FastEmbed с открытой моделью `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`. При ошибке он явно переходит на лексический поиск. Реальная загрузка FastEmbed в экзамене не проверялась.

**Данные и разметка.** В индекс попадают только утверждённые статьи, шаблоны и обезличенные обращения с подтверждённым оператором результатом. Исходный текст пользователя и инструкции из документов не становятся доверенными указаниями.

**Метрики.** Отдельно измеряются Recall@K, MRR, доля запросов с достаточным основанием и задержка поиска. Качество поиска не смешивается с качеством текста черновика.

**Сбой и неопределённость.** Если нет подходящей статьи, источники противоречат друг другу или основания недостаточны, уверенный ответ не формируется: используется безопасный шаблон либо тикет передаётся оператору.

## Генерация черновика

**Задача.** Сформулировать черновик по уже найденному и проверенному основанию, когда шаблон недостаточно удобен для оператора.

**Базовый и кандидатный подход.** Базовый вариант — параметризованный шаблон без LLM; он реализован по умолчанию. Необязательный `OpenRouterGenerator` получает по HTTP только обезличенный тикет и одну утверждённую статью. Модель, тайм-аут и лимит токенов задаются локальным конфигурационным файлом; живой вызов с ключом не проводился.

**Данные и разметка.** Нужны утверждённая база знаний, обезличенные примеры, правки операторов и отложенные оценки качества. Проверенные правки могут пополнять набор оценки и только затем — материал для улучшения системы.

**Метрики.** Оцениваются обоснованность источниками, доля неподтверждённых или небезопасных ответов, принятие черновиков операторами, объём правок, задержка и стоимость на тикет. Эти показатели измеряются отдельно от поиска.

**Сбой и неопределённость.** LLM не используется в быстром контуре, для решения о риске или без найденного основания. Пустой ответ, ошибка, тайм-аут, небезопасный текст или недостаточная обоснованность переводят тикет оператору. В PoC отказ адаптера проверен локально; повторные попытки относятся к целевой асинхронной системе.

## Выбор порогов и проверка качества

1. Исторические данные делятся по времени на обучающую и отложенную проверочную выборки; обращения одного инцидента не должны попадать в обе части.
2. Для маршрутизации сравниваются правила, частый маршрут и TF-IDF с линейной моделью. Для риска отдельно сравниваются правила и классификатор.
3. Граница уверенности выбирается на размеченной отложенной выборке. При необходимости оценка уверенности калибруется; выбор делается с учётом стоимости ошибок, доступной нагрузки операторов и обязательного ограничения на полноту опасных классов.
4. Поиск проверяется на запросах с эталонными статьями, а генерация — на небольшом наборе обращений с выборочной оценкой оператором.
5. При нехватке разметки система расширяет зону передачи оператору, а не придумывает производственный порог. Детерминированные примеры PoC служат только воспроизводимой проверкой поведения.
